# Contributing

Thanks for your interest.

- **Open an issue first** for anything beyond a small fix, so we can agree the approach before you write code.
- **Show the evidence.** A bug report or behaviour change needs steps to reproduce, plus logs or output with secrets removed.
- **No personal data.** Use documentation values in code, tests and issues: MACs `02:00:00:00:00:xx`, addresses from `192.0.2.0/24`, domains `example.com` / `example.home`.
- **Keep changes focused.** One change per pull request; don't reformat unrelated code.
- **Run the tests** before opening a pull request (see the Commands section in [CLAUDE.md](CLAUDE.md)).
- Add a line under `Unreleased` in [CHANGELOG.md](CHANGELOG.md) for anything a user would notice.
