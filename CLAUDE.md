# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

vlc-mcp is a Python MCP server (stdio) that lets an AI client play and control videos in VLC through VLC's HTTP interface. All tools live in `src/vlc_mcp/main.py`.

## Commands

- Python: always `uv run …`; never bare `python` / `pip` (system Python isn't on PATH).
- Lint / format: `uvx ruff check` and `uvx ruff format` (config in `pyproject.toml`, line length 120). Lint what you touch; don't mass-fix unrelated code.
- Run: `uv run vlc-mcp`. It exits immediately unless `ROOT_VIDEO_FOLDER` is set.
- Inspect tools: `npx @modelcontextprotocol/inspector uv run vlc-mcp`.
- Build check: `uv build --wheel -o <scratch dir>`, then confirm the wheel contains `vlc_mcp/main.py`.
- Tests: `uv run pytest`. They mock VLC by patching `main.vlc_get` (the `vlc` fixture in `tests/conftest.py`), so no VLC is needed. Add a test with each tool change.
- End-to-end checks need a running VLC with its HTTP interface on. **Don't drive a live VLC without asking**: tools start full-screen playback and change the volume.
- If an MCP client is running this package, `uv run` can fail rebuilding the `.venv` entry-point exe (os error 32). Use `uv run --no-sync …`.

## Architecture rules

- Uses `mcp` 2.x `MCPServer` (`mcp.server.mcpserver`), not 1.x FastMCP. Tools take no `Context`; `ctx.info()`/`ctx.error()` are deprecated (SEP-2577). Check 2.x APIs via Context7, not memory.
- Logs go to stderr via `logger`; stdout is the protocol stream. Never `print()` to stdout.
- Tools are async: use `await asyncio.sleep`, never `time.sleep`.
- All VLC calls go through `vlc_get` / `vlc_command` / `vlc_json`. Parse JSON with `vlc_json`: VLC sends UTF-8 without a charset, so `response.json()` / `.text` mis-decode it as ISO-8859-1.
- VLC's HTTP commands are documented in `docs/requests.txt`. Check it before adding a command.
- VLC volume is 0–512 (256 = 100%); tools expose 0–200%.
- Tool paths are relative to `ROOT_VIDEO_FOLDER` via `resolve_media_path` (`os.path.join`, so absolute paths pass through).
- Adding or changing a tool: update the README tools table and the CHANGELOG `Unreleased` section.

## Gotchas

- `VLC_HTTP_PASSWORD` comes from the environment; never write it into the repo. The fallback `your_password` makes VLC return 401, so a 401 means the password isn't set, not a code bug.
- `show_video` shells out to `mediainfo`, which must be on PATH.
- `remove_playlist_item` uses `pl_delete`, which VLC marks unsupported. Don't "fix" it.
- `src/vlc_mcp/_version.py` and `vlc_mcp.egg-info/` are generated by the build. Don't hand-edit them.
- `update-readme-date.yml` rewrites the `_Last updated: …_` line in README.md on every push to `main`. Keep that line's format.
- Every workflow `uses:` is pinned to a full commit SHA with the version as a trailing comment (`actions/checkout@<sha> # v7.0.1`); super-linter's zizmor check fails on tags.

## Versioning

- The version comes from git tags via setuptools_scm; no file holds it. To release, move CHANGELOG `Unreleased` entries under the new version, commit, then tag `vX.Y.Z` and push the tag. Not published to PyPI; users install from GitHub.

## Git

Short imperative one-line subjects (e.g. "Add equalizer tools"), not Conventional Commits. Commit straight to `main`. Pull before committing. Never paste `git status` output as the message. Don't push without explicit go-ahead; the push-guard hook asks before any push to `main`.
